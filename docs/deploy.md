# Выкладка expresscooling.kz: пошаговая инструкция

Этот документ — для владельца бизнеса, а не для программиста. Здесь нет ничего, что требует умения писать код: команды приводятся отдельными строками, чтобы их можно было просто скопировать и вставить в терминал. Отправку кода в репозиторий, создание проекта на Cloudflare и покупку домена нужно сделать самостоятельно — эти шаги затрагивают ваши собственные аккаунты, и делать их за вас не будет никто. Ниже расписано, что именно нажимать и в каком порядке, чтобы не застрять.

Проходите по разделам по порядку — каждый следующий опирается на предыдущий.

## 1. Что уже готово, а что предстоит

Готово:
- Сайт полностью собран, сверен с макетом и проверен по скорости — все четыре оценки Lighthouse (Производительность, Доступность, Лучшие практики, SEO) на мобильном профиле равны 100.
- Весь код лежит в ветке `feat/landing` в этой папке на вашем компьютере.
- Репозиторий на GitHub уже создан и подключён: `https://github.com/BDCasper/expresscooling.git`.

Предстоит (и это то, что описано ниже по шагам):
- Отправить код с вашего компьютера в этот репозиторий на GitHub — сейчас там кода ещё нет.
- Купить домен `expresscooling.kz`.
- Завести проект на Cloudflare Pages, который будет собирать сайт из репозитория и показывать его в интернете.
- Привязать купленный домен к этому проекту.

## 2. Отправка кода в репозиторий

Прежде чем отправлять что-либо на GitHub, стоит один раз посмотреть на сайт вживую у себя на компьютере — это тот же самый файл, что попадёт на сервер, только открытый локально. Выполните по очереди, в папке проекта:

```bash
npm run build
npm run preview
```

Первая команда собирает сайт, вторая — поднимает его на локальном адресе `http://localhost:4321`. Откройте этот адрес в браузере, полистайте страницу, проверьте, что всё выглядит так, как ожидалось. Когда закончите смотреть, вернитесь в терминал и нажмите `Ctrl+C`, чтобы остановить предпросмотр.

Если всё в порядке, отправляйте код:

```bash
git branch -M main
git push -u origin main
```

Первая команда переименовывает текущую рабочую ветку в `main` — это имя, которое GitHub и Cloudflare ожидают увидеть как основное. Вторая — отправляет весь код на GitHub и запоминает эту ветку как ту, куда пойдут будущие отправки. После этой команды на странице репозитория `https://github.com/BDCasper/expresscooling` появится весь код сайта.

## 3. Покупка домена на ps.kz

Домен `expresscooling.kz` покупается на сайте [ps.kz](https://ps.kz) — это казахстанский регистратор, через который оформляются домены в зоне `.kz`.

На что обратить внимание при покупке:
- Регистрируйте домен на то же юридическое или физическое лицо, что указано в реквизитах бизнеса — при регистрации `.kz` иногда запрашивают подтверждающие документы, и они должны совпадать с данными в форме.
- Домены в зоне `.kz` проходят проверку регистратором (KazNIC) перед активацией. Это нормальная процедура для этой доменной зоны, а не что-то специфичное для ps.kz.
- После оплаты и подтверждения домен появится в личном кабинете ps.kz в разделе управления доменами — там же позже нужно будет поменять серверы имён (шаг 5).

**Важно:** делегирование домена `.kz` — то есть момент, когда изменения серверов имён реально начинают действовать в интернете, — может занимать до нескольких часов после того, как вы их прописали. Если через десять минут после смены серверов имён домен ещё не открывается — это ожидаемое поведение, а не поломка. Стоит подождать несколько часов и проверить снова, прежде чем искать проблему.

## 4. Создание проекта на Cloudflare Pages

1. Зайдите в панель Cloudflare (`dash.cloudflare.com`), заведите аккаунт, если его ещё нет.
2. Найдите раздел **Workers & Pages** в боковом меню, нажмите **Create** (Создать), затем выберите вкладку **Pages** и вариант подключения к репозиторию Git (обычно называется «Connect to Git» или «Импортировать репозиторий Git»).
3. Разрешите Cloudflare доступ к вашему аккаунту GitHub и выберите репозиторий `BDCasper/expresscooling`.
4. В настройках сборки укажите:
   - **Framework preset (заготовка фреймворка):** Astro, если такой пункт есть в списке — Cloudflare сам подставит команды ниже.
   - **Build command (команда сборки):** `npm run build`
   - **Build output directory (каталог с результатом сборки):** `dist`
   - **Node version (версия Node.js):** 24 — это обычно отдельное поле в настройках проекта (иногда «Environment variables» → `NODE_VERSION`), при необходимости впишите значение `24` туда.
5. Переменные окружения на этом шаге оставьте пустыми — они понадобятся позже, в разделе 6.
6. Запустите сборку («Save and Deploy» или аналогичная кнопка).

**Важно:** команда сборки, которую запускает Cloudflare, — это ровно `npm run build` и ничего больше. Тесты сайта (`npm test`) в сборку не входят и никогда не запускаются на сервере Cloudflare — это часть работы над сайтом, которая уже завершена, а не часть выкладки.

После первой успешной сборки Cloudflare выдаст временный адрес вида `<название-проекта>.pages.dev`. Откройте его и убедитесь, что сайт открывается: страница загружается, шрифты и фотографии на месте, кнопки WhatsApp кликабельны. Это тот же самый адрес, по которому ниже (раздел 7) нужно будет прогнать Lighthouse.

## 5. Привязка домена к Cloudflare и проекту

Порядок обратный тому, что можно было бы ожидать: сначала домен добавляется в Cloudflare как отдельная зона, и только потом Cloudflare выдаёт вам серверы имён, которые нужно прописать на ps.kz.

1. В панели Cloudflare найдите раздел добавления сайта (обычно кнопка **Add a site** / «Добавить сайт» на главном экране аккаунта) и введите `expresscooling.kz`.
2. Cloudflare покажет два адреса серверов имён (NS-записи) — что-то вроде `xxx.ns.cloudflare.com` и `yyy.ns.cloudflare.com`. Запишите их — это то, что нужно перенести на ps.kz.
3. Зайдите в личный кабинет ps.kz, найдите управление доменом `expresscooling.kz`, там — раздел с серверами имён (может называться «NS-записи», «DNS-серверы» или «Управление серверами имён»). Замените серверы имён, которые там стоят по умолчанию, на два адреса от Cloudflare из предыдущего шага.
4. Подождите делегирования — как написано в разделе 3, это может занять до нескольких часов. Cloudflare сам сообщит (обычно письмом на почту и статусом в панели), когда увидит, что домен переключился на его серверы имён — зона перейдёт в статус «Active» («Активна»).
5. После того как зона стала активной, вернитесь в проект Cloudflare Pages, откройте раздел **Custom domains** («Пользовательские домены») и добавьте туда `expresscooling.kz` (и, если нужно, `www.expresscooling.kz`).
6. Cloudflare автоматически выпустит SSL-сертификат для домена — это то, что даёт сайту `https://` и замочек в адресной строке браузера. Проверить это можно двумя способами: в панели Cloudflare статус сертификата в разделе **SSL/TLS** должен стать «Active», а в браузере при открытии `https://expresscooling.kz` не должно быть предупреждения о небезопасном соединении. Выпуск сертификата обычно занимает от нескольких минут до пары часов после того, как домен подключён.

## 6. Включение счётчика посещений (Google Analytics и Google Ads)

Сайт устроен так, что счётчик Google не грузится вовсе, пока в настройках проекта не указаны два идентификатора. Это не забытая настройка, а сознательный выбор: пока рекламных аккаунтов нет, считать нечего, а лишний код только замедлял бы сайт. Поэтому, пока переменные окружения пустые, отсутствие счётчика — это нормальный, ожидаемый режим.

Когда рекламные аккаунты будут созданы (как их завести и откуда взять сами идентификаторы — подробно расписано в `docs/google-ads.md`), включить счётчик нужно так:

1. В панели Cloudflare откройте настройки проекта Pages, раздел переменных окружения (**Environment variables** / «Переменные окружения»).
2. Добавьте две переменные:
   - `PUBLIC_GA_ID` — идентификатор Google Analytics (вид `G-XXXXXXXXXX`).
   - `PUBLIC_ADS_ID` — идентификатор Google Ads (вид `AW-XXXXXXXXX`).
3. Сохраните и **запустите пересборку сайта** — обычно кнопка «Retry deployment» или создание нового деплоя. Без пересборки новые значения не попадут в собранные страницы: сайт продолжит отдавать ту версию, где идентификаторы были пустыми.

## 7. Проверка после выкладки

После того как сайт открывается по адресу `https://expresscooling.kz` (или по временному `*.pages.dev`, если домен ещё не подключён), проверьте вручную:

- Страница открывается без ошибок, шрифты подгружаются (текст не «дефолтным» системным шрифтом секунду-другую, а потом Onest), все фотографии на месте.
- Кнопки WhatsApp открывают чат с настоящим номером компании.
- Звонок по телефонному номеру срабатывает с мобильного телефона (нажатие на номер должно сразу открывать приложение звонилки с уже набранным номером).

Затем прогоните Lighthouse по живому адресу — так же, как раньше замеряли локально, только теперь по-настоящему, через интернет:

```bash
npx lighthouse https://expresscooling.kz --preset=perf --form-factor=mobile --output=json --output-path=./lh-live.json --quiet
node -e "const r=require('./lh-live.json');console.log('Performance:',r.categories.performance.score)"
```

Сравните результат с локальными цифрами (все четыре оценки по 100, отрисовка крупнейшего элемента около 1.75 секунды). **Локальный замер оптимистичнее живого**: он не учитывает настоящую сеть, задержки настоящих серверов и реальное расстояние до посетителя — небольшое падение цифр на живом адресе по сравнению с локальными ожидаемо и само по себе не повод для тревоги, если оценка остаётся высокой.

**Отдельно — второй замер с включённым счётчиком.** Пока проверяли сайт в среде разработки, замер с принудительно включённым тегом Google оказался недостоверным: тестовое окружение было подключено к интернету через аномально медленный канал именно до серверов Google, из-за чего Lighthouse иногда занижал оценку без всякой связи с реальным качеством кода. Достоверную цифру можно получить только на живом адресе. Поэтому: после того как в разделе 6 вы включите `PUBLIC_GA_ID` и `PUBLIC_ADS_ID` и пересоберёте сайт, повторите ровно те же две команды Lighthouse ещё раз по `https://expresscooling.kz` — теперь счётчик уже будет частью того, что измеряется, и результат будет отражать сайт таким, каким его увидят настоящие посетители после запуска рекламы.

## 8. Памятка на будущее — что нужно пересобирать вручную

Эти три вещи не обновляются сами по себе. Ничего не сломается, если о них забыть, но результат будет незаметно устаревшим, а не сразу очевидной ошибкой — поэтому они вынесены отдельно.

**Картинка для соцсетей (`public/og-image.jpg`).** Эта картинка показывается, когда кто-то делится ссылкой на сайт в WhatsApp, Telegram или соцсетях — на ней телефон компании и фотография мастера. Она собирается один раз командой и после этого просто лежит в репозитории как обычный файл — сайт не пересобирает её сам при каждой выкладке. Если в `src/data/site.ts` сменится телефон или заменится фотография мастера, картинку нужно пересобрать вручную:

```bash
npm run og:build
```

и закоммитить получившийся файл. Если этого не сделать, при расшаривании ссылки будет показываться уже неверный телефон или старое фото — и никто не заметит расхождения, пока кто-нибудь не поделится ссылкой и не покажет скриншот.

**Визуальные эталоны (`tests/e2e/visual.spec.ts-snapshots/`).** Это скриншоты-образцы, с которыми автоматически сверяется внешний вид сайта при тестировании. Они привязаны к операционной системе, на которой были сняты (сейчас — Windows), и не подойдут напрямую, если разработка когда-нибудь переедет на Linux или macOS. Подробности — что делать в этом случае и как пересобрать эталоны — расписаны в `docs/visual-check.md`.

**Замена стоковых фотографий на настоящие.** Часть фотографий на сайте сейчас временные (стоковые), а не снятые на реальных объектах. Список всех изображений с подписями к ним — в файле `src/data/assets.ts`, сами файлы — в папке `src/assets/images/`. Чтобы заменить фотографию на настоящую, достаточно положить новый файл под тем же именем на то же место — менять код не нужно.

## 9. Что делать, если что-то сломалось

**Сборка на Cloudflare упала (в панели статус деплоя — «Failed»).** Откройте лог сборки в панели Cloudflare Pages (кнопка на странице деплоя, обычно «View build log» или «View details») и посмотрите, на какой команде и с каким сообщением она остановилась. Чаще всего причина — не в самом коде, а в настройках: сверьте, что команда сборки указана ровно как `npm run build`, каталог результата — ровно `dist`, а версия Node — `24`. Если лог указывает на нехватку какого-то пакета — попробуйте пересобрать заново («Retry deployment»): иногда сборка падает из-за временной проблемы на стороне Cloudflare, а не из-за кода.

**Домен не открывается.** Сначала проверьте, сколько времени прошло с момента смены серверов имён на ps.kz — до нескольких часов на делегирование `.kz`-домена это нормально (раздел 3). Если прошло больше суток, а сайт всё ещё не открывается: проверьте в панели ps.kz, что серверы имён указаны без опечаток и ровно те два адреса, что выдал Cloudflare; проверьте в панели Cloudflare, что зона `expresscooling.kz` в статусе «Active», а не «Pending Nameservers» («Ожидание серверов имён»); проверьте в разделе SSL/TLS, что сертификат выпущен, — до его выпуска браузер может показывать предупреждение о небезопасном соединении даже при правильно настроенном домене.

**Счётчик не считает заявки.** Первым делом проверьте самое частое: были ли внесены переменные `PUBLIC_GA_ID` и `PUBLIC_ADS_ID` в настройках проекта Cloudflare и была ли после этого запущена пересборка сайта (раздел 6) — без пересборки новые значения не попадают в уже собранные страницы, и сайт продолжает показывать себя так, будто счётчика вообще нет. Если переменные заданы и сайт пересобран, а событий всё ещё не видно — откройте `docs/google-ads.md`, раздел «Как проверить, что всё работает»: там расписано, что счётчик у этого сайта загружается только после первого действия посетителя (прокрутка, касание, клик), поэтому проверка сразу после открытия страницы без единого движения мышью ничего не покажет — это не поломка.
